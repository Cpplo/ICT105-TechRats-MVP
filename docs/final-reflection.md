
# Final Reflection

## 1. What We Built
We built a web-based **Student Internship & Entry-Level Job Platform** prototype that helps university students and fresh graduates discover trustworthy beginner-friendly jobs, while helping employers recruit verified early-career talent.

The prototype includes:
- Simulated login and role selection
- Student and employer dashboards
- Student profile and verification flow
- Employer profile and company verification flow
- Job browsing, search, and filtering
- Job detail pages with verification badges
- Job application submission and tracking
- Saved jobs
- Messaging
- Applicant management
- Reporting suspicious jobs
- Admin verification and report review
- Landing page and go-to-market materials
- Product metrics and validation documentation

## 2. What We Learned About Users
We learned that users care most about **trust, clarity, and simplicity**.

From students, we learned:
- They want internships and entry-level jobs that are truly beginner-friendly
- They need clear eligibility requirements
- They trust verified employers more
- They value resume upload, application tracking, and saved jobs

From employers, we learned:
- They want a simple way to find beginner candidates
- They need applicant profiles with useful information
- They want verification to improve credibility
- They prefer a clear workflow for reviewing and updating applications

From testing, we also learned:
- Users understand the browsing and detail flow well
- Verification badges improve confidence
- Some important actions still need to be more visible

## 3. What We Learned About Requirements
We learned that the MVP requirements must stay tightly focused on the core workflows.

The most important requirements were:
- Simulated login and role selection
- Student and employer verification
- Beginner-friendly job filtering
- Job detail viewing
- Application submission and tracking
- Employer applicant management
- Report handling
- Verified badge display
- Employer posting restriction

We also learned that not every possible feature should be included in the MVP. Features like real authentication, real database storage, secure file handling, and AI recommendations are better saved for later development.

## 4. What We Improved After Testing
After testing, we improved or reinforced:
- Verification-focused workflows
- Role-based navigation
- Beginner-friendly job labels
- Trust signals through verified badges
- Dashboard summaries
- Admin review flow
- Landing page clarity and acquisition messaging

Testing also showed that we should keep improving:
- Visibility of the application tracker
- Visibility of the report button
- Clarity of verification labels
- Mobile spacing and responsiveness
- Confirmation messages after actions

## 5. What Was Difficult Technically
The most difficult technical parts were:
- Keeping the prototype interactive without a real backend
- Managing simulated data consistently across screens
- Making role-based flows work cleanly in one front-end prototype
- Designing admin, student, and employer workflows without making the UI too crowded
- Keeping the interface responsive while preserving the same visual style
- Balancing prototype realism with the limitations of static/local data

Another challenge was keeping the project aligned with documentation, requirements, and the actual prototype so that the report, landing page, and demo all matched the same product story.

## 6. What We Would Improve Next
If we continued the project, we would improve:
- Real authentication and role-based security
- Real database storage and persistence
- Secure upload and storage for resumes and verification documents
- Better admin analytics and moderation tools
- Real-time messaging
- Improved filtering and search
- Stronger mobile optimization
- Better feedback and confirmation states
- AI-based recommendations and verification assistance
- Email notifications and calendar integration
- Employer analytics dashboard
